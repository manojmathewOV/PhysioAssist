# Research: decisions, alternatives and blind spots

This is the portable evidence register for the runbook, not a new CCore Research runtime store. [research.json](research.json) binds sources, support limits, open questions and affected gates. [CCore evidence](evidence/CCORE_TOOLING.md) states whether native Research effects actually succeeded.

## What the evidence changes

The user scope eliminates clinician portal, clinical cloud sync and Android release from MVP. Stable identities and small interfaces preserve future expansion without implementing those systems now. The existing code is reused; the latest author report is retained as testimony until an independent replay.

Registration needs an explicit meaning. A local profile can work offline; real federated registration has account lifecycle obligations and still does not back up clinical records. The plan does not select an identity backend on the owner's behalf.

Local storage is the principal architecture experiment: measured pagination, transactional migrations, protection/backup policy and controlled media caching. A higher array cap does not establish low memory use or durable retention.

Native OS services are candidates for speech, local reminders, credentials and camera acceleration. They are not a reason to discard an estimator with useful evidence or to introduce health-platform integrations without a specific outcome. Feature availability, actual release-build cost and method compatibility must be measured.

## Discriminating experiments

Q01: implement a synthetic onboarding journey with explicit local-data wording; test account cancellation, offline restart, revocation and switching profile. Decide identity-only service only after D01.

Q02: compare baseline storage startup/read/write/memory with a transactional paginated implementation using synthetic large history, interruption and disk-full tests. Keep the old data until a verified migration/recovery point.

Q03: replay exact current production reducers/hooks/screens, including contradictory event order, schedule-only edits, expiry/foreground and Start-time validation. Do not merely rerun old test strings.

Q04: attempt illegal cross-protocol variant selection and a missing source/brace/assistance field. Confirm safe activities remain usable without pretending the patient has clinical clearance for others.

Q05: compare identical held-out recordings and reference definitions across candidate estimators; report error, coverage and false withholding separately. Measure on supported hardware, not only simulator time.

Q06: execute native cloud build -> simulator -> images -> retrieval -> visual findings. A workflow declaration is only infrastructure evidence; retrieved screenshots prove a different step.

Q07: enumerate waking-window boundaries, missed reminders, changed schedule and abandoned rounds; keep clinical dose/anchor choices explicit and do not use notification delivery as completion.

Q08: distinguish Check from Do and compare only compatible observations. Design test-retest/independent-reference work before claiming clinically meaningful improvement.

## Review discipline

Record source identity/date, uncertainty, contradictory observations, decision owner, chosen option, scope and reopen condition. Current evidence may supersede an interpretation, not erase its history. A proposed experiment, executed test, observed effect and accepted outcome are different states.
